## 1. 项目背景和当前目标 (Project Background)

### 1.1 行业现状与机会点

目前的健康管理市场存在“数据丰沛但认知贫瘠”的断层。

* **市场痛点：**

  * **缺乏系统性思维：** 现有产品多为单点监测（心率、步数），缺乏一套能够整合全身信息、具有大局观的健康思考体系。

  * **专业门槛鸿沟：** 专业的健康管理方案仅存在于极少数专家脑中，普通用户无法获取系统性的、开源的健康哲学指导。

* **切入契机：**

  1. **中医体系优势：** 中医（特别是经方派）天生具备整体观和系统论，能够将身体细微变化转化为辩证的健康状态。

  2. **独家算法突破：** 拥有将 Raw Data（原始波形/HRV）精准映射为中医“望闻问切”核心信息的能力。

  3. **技术范式转移：** 大语言模型（LLM）的推理能力与 Agent 的 MCP 能力，使得“专业思维模型化”、“报告定制化”、“界面高度自定义”成为可能。

### 1.2 动机 (Motivation)

* **核心逻辑：** 以中医经方派思维为“大脑”，以独家算法为“感官”，实现从原始生理数据到系统性健康状态的“降维翻译”。

* **产品愿景：** 打造一个AI健康管理师，提供真正具有大局观、可理解、可定制的健康管理决策。

### 1.3 核心业务目标

* **核心定位：** 基于中医经方思维的AI健康管理师。

* **短期目标：**

  * 验证算法结果 -> 中医四诊合参所需的全部文字信息 -> 个性化的健康报告流程，实现首个基于经方思维的全方位健康报告。

* **长期目标：**&#x20;

  * 根据用户反馈与指标分析体系，持续优化个性化定制报告能力。

  * 迭代技术路径，降低模型推理成本。

## 2. 用户角色与画像 (User Persona)

### 2.1 核心竞争属性

1. **可理解：** 将复杂的生理数据转化为用户本身就理解的身体情况。

2. **可定制（Agent & MCP 生态）：** 界面不再固定。根据用户关注点，以及大模型推理出的需要注意的身体方面，生成个性化的报告以及建议，并且利用 MCP/function calling 能力调用不同指标可视化模块，拼装出最符合用户当前需求的数据看板。

### 2.2 典型用户画像

1. **职场精英**

   * **核心关注点**：压力管理、长期疲劳、情绪波动（易怒）。

   * **核心优势应用**：

     * **核心算法**：通过佩戴式设备算法初步获得中医体质基础数据。

     * **经方思维**：大模型通过四诊合参逻辑推理出中医“心阴虚”状态，并结合压力关注点提供病理反馈。

     * **个性化**：提供定制化压力分析报告，利用 MCP 动态加载与焦虑、自主神经系统相关的 UI 组件。

   * **理想场景**：应用告知用户当前处于“心火旺、阴虚”状态，建议今日取消高强度会议，提高休息优先级并配合冥想。

2. **亚健康人群**

   * **核心关注点**：状态不明、全方位调理、体态及肥胖管理。

   * **核心优势应用**：

     * **个性化**：基于经方派思维，Agent 过滤掉冗余信息，仅提供用户当下最需关注的 1-2 个核心健康问题。

     * **UI模块化**：看板仅显示与当前问题（如：痰湿/肥胖）相关的动态组件。

   * **理想场景**：界面极其简洁，只显示身体最紧迫的问题分析及针对性的行动闭环。

3. **中医养生爱好者**

   * **核心关注点**：节气养生、体质长期调理、经络健康。

   * **核心优势应用**：

     * **个性化**：基于用户对中医的了解程度，提供包含专业术语（如“表寒里热”）的深度报告，增强可解释性。

     * **经方思维**：基于开源经方体系提供系统的饮食、作息及草本调理方案。

   * **理想场景**：应用告知用户体质在冬季易生寒湿，检测到今早脉象（算法模拟）沉弱，精准建议早餐加入干姜以温里。

## 5. **成功指标（KPI）和发布条件**

### 5.1 现阶段（产品验证）

#### 5.1.1 开发/内测

* **主指标**

  * **报告真实性**：AI报告和真人中医医师判断一致性评分。

* **其他需注意指标建议：**

  * **映射覆盖率 (Mapping Coverage)：** 原始 Raw Data 能成功映射到中医维度的比例（避免出现“无法识别”的情况）。

#### 5.1.2 灰度测试/拟发布

* **主指标**

  * **次日留存率**：如果用户看完第一份基于经方思维的报告后觉得“说得太准了”并愿意明天再来看看，这代表产品验证成功

* **其他需注意指标建议：**

  * **推理时延 (Reasoning Latency)：** Agent 利用 MCP 调用组件并生成报告的总时长。如果超过 5-10 秒，未来用户流失率会很高。
